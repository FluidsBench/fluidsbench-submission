# DrivAerML native profile truth export

`scripts/export_drivaerml_native_profile_truth.py` publishes the inactive
website/reference truth for all 484 pinned DrivAerML cases. It verifies the
retained producer support before reading truth values and emits compact,
hash-bound JSON. It does not change a scoring weight, enable the relative
profile format, open submissions, or complete owner approval.

The publication receipt correctly preserves that non-approval state at its
generation time. Neil Ashton subsequently approved the cited native profile
evidence and scientific decisions on 2026-08-28 in
[`../evidence/owner-scientific-approval-2026-08-28.json`](../evidence/owner-scientific-approval-2026-08-28.json).
That later approval does not rewrite this immutable receipt or open submissions.

## Inputs

The command requires explicit paths to all six authorities:

1. `native-source-pin.json`, whose exact required SHA-256 is
   `4fc9077f8f23f4994c98f4d0e7a17aef7b998de4c996638e3a8a616b6d923fdd`;
2. a local assembly of `neashton/drivaerml` revision
   `7a5c0948ce27be709b1116a3a190f806e7a8f79f`;
3. the 484 constant-velocity mapping directories and receipts;
4. the relative-v3 producer root containing the velocity-placement,
   velocity-mapping, and relative-Cp manifests and all case artifacts;
5. the 484-case constant-Cp campaign root; and
6. the retained all-case native-volume audit.

The tool rejects a missing case, extra case, changed aggregate, changed
per-case producer file, non-replaying receipt, wrong source binding, malformed
or incomplete mapping, out-of-range native cell/polygon ID, changed native
boundary bytes, producer/native `pMeanTrim` disagreement, or changed Cp formula. Large
native files and producer artifacts remain external; only compact truth,
receipts, and hashes are publication outputs.

## Parallel generation and deterministic assembly

`case` mode uses zero-based pin order and is safe for a 484-task scheduler
array. Every task writes one file atomically:

```bash
python scripts/export_drivaerml_native_profile_truth.py \
  --mode case \
  --case-index "$SLURM_ARRAY_TASK_ID" \
  --native-source-pin benchmark-specs/drivaerml/proposal/native-source-pin.json \
  --dataset-root /path/to/pinned/drivaerml \
  --constant-velocity-receipts-root /path/to/constant-velocity/receipts \
  --relative-producer-root /path/to/relative-v3-producer \
  --constant-cp-campaign-root /path/to/constant-cp-campaign \
  --native-volume-audit benchmark-specs/drivaerml/evidence/native-volume-equal-cell-primary-all484.json \
  --output-dir /path/to/native-profile-truth-v3 \
  --evaluator-git-revision <FULL_LOCAL_GIT_COMMIT>
```

Use the same paths, source tree, full Git commit, and output directory for all
tasks. After all tasks succeed, `assemble` mode requires the eight explicit
official split indexes:

```bash
python scripts/export_drivaerml_native_profile_truth.py \
  --mode assemble \
  --native-source-pin benchmark-specs/drivaerml/proposal/native-source-pin.json \
  --dataset-root /path/to/pinned/drivaerml \
  --constant-velocity-receipts-root /path/to/constant-velocity/receipts \
  --relative-producer-root /path/to/relative-v3-producer \
  --constant-cp-campaign-root /path/to/constant-cp-campaign \
  --native-volume-audit benchmark-specs/drivaerml/evidence/native-volume-equal-cell-primary-all484.json \
  --output-dir /path/to/native-profile-truth-v3 \
  --evaluator-git-revision <FULL_LOCAL_GIT_COMMIT> \
  --split-index full=benchmark-specs/drivaerml/splits/full.json \
  --split-index medium=benchmark-specs/drivaerml/splits/medium.json \
  --split-index scarce=benchmark-specs/drivaerml/splits/scarce.json \
  --split-index super_scarce=benchmark-specs/drivaerml/splits/super_scarce.json \
  --split-index geometry=benchmark-specs/drivaerml/splits/geometry.json \
  --split-index high_drag=benchmark-specs/drivaerml/splits/high_drag.json \
  --split-index low_drag=benchmark-specs/drivaerml/splits/low_drag.json \
  --split-index rear_separation=benchmark-specs/drivaerml/splits/rear_separation.json
```

The default is eight cases per chunk. Re-run both phases with `--check` to
verify byte-for-byte deterministic output without overwriting it. Case
artifacts bind the exact exporter source hash and evaluator commit, so assembly
rejects output generated by a different source snapshot.

## Output contract

The schema version is `3.0`. It is a new immutable publication; existing
native-v2 bytes remain unchanged. The output tree contains:

- `cases/run_N.json`: atomic build-stage artifacts (not browser-published);
- `chunks/chunk-NNN.json`: website payloads, eight cases per chunk by default;
- `splits/*.json`: eight thin indexes referencing immutable chunk hashes;
- `index.json`: exact ordered 484-case chunk locations and all public artifact
  bindings;
- `provenance.json`: source, producer, evaluator, identity, and truth-method
  bindings; and
- `release-receipt.json`: a closed, non-activating publication receipt.

Each case has exactly 40 ordered series: 16 constant velocity, 16 relative-v3
velocity, four constant Cp, two relative Cp centreline aliases, and two
materialized relative Cp cuts. Materialized rows retain aligned
`sample_index`, `raw_native_cell_id`, `coordinate`, and `value` arrays.
Unsupported velocity samples are excluded from value arrays but preserved as
`{sample_index, coordinate, reason}` records. Segment descriptors prevent a
consumer from joining across an unsupported interior gap. Shared Cp aliases
contain only the canonical constant-support reference required by the current
representation.

Public coordinate vocabulary matches the current schema-v3 profile fixture:
constant velocity uses `distance_m`, relative velocity uses
`normalized_arc_length`, and every materialized Cp series uses
`arc_length_m`. Producer-native fields such as `line_fraction`,
`arc_length_end_m`, and `interval_arc_end_m` remain named in provenance and
support verification, but are normalized to those public labels on export.

Native-v3 additionally gives each of the six materialized Cp series an aligned
display coordinate:

```text
display_coordinate_id   = streamwise_x_m
display_coordinate_unit = m
display_coordinate[i]   = 0.5 * (endpoint_start_m[i][0]
                                 + endpoint_end_m[i][0])
```

The endpoints are the retained producer plane-intersection segment endpoints,
so the midpoint lies on the precise cut segment represented by that row. All
3,508,520 materialized Cp rows across the 484 cases contain finite endpoint
3-vectors and replay their retained segment length; no native-cell-centre
fallback or mixed coordinate definition is used. The arithmetic is binary64
over raw VTP coordinates in metres. Values remain in producer row order and
are not shifted, normalized, sorted, interpolated, or resampled. Physical x
may repeat or reverse locally. It is a display/comparison coordinate only;
`coordinate_id=arc_length_m`, its array identity, prediction compatibility,
and every scoring calculation are unchanged. Relative centreline aliases do
not duplicate arrays: consumers resolve their display coordinate from the
canonical constant-Cp series.

Every case, chunk, split index, master index, provenance record, and release
receipt repeats the exact declaration below. A website consumer can therefore
distinguish pinned native-CFD truth from an analytical or transport dummy
without inferring it from filenames or surrounding prose:

```json
{"analytical_dummy":false,"native_quantity_source":"pinned_drivaerml_cell_data","source_kind":"native_cfd"}
```

Velocity truth is `norm(UMeanTrim) / 38.889`; Cp truth is
`2 * pMeanTrim / (38.889 ** 2)`. The exporter reads only the mapped
`UMeanTrim` tuples by exact seek into the uncompressed inline VTK base64
payload. For Cp, it fully hashes each pinned native `boundary_N.vtp`, requires
the exact pinned size and SHA-256, parses the declared `NumberOfPolys`, and
directly gathers `pMeanTrim` at the union of every constant and moving-relative
producer `raw_polygon_id`. Every producer pressure value must exactly equal the
selected native Float32 value. Published Cp is computed from those selected
native values, never from the producer JSON copy. The retained volume audit
binds the full `UMeanTrim` payload, while each case records independent
identities over the exact selected velocity and pressure IDs/values. Pre/post
file stability is checked during hashing and reading, but host paths, device
and inode numbers, and timestamps are never serialized.

The provenance, index, and release receipt retain recomputed per-family
materialized sample, unsupported-sample, and segment counts. Generation fails
unless the known producer totals replay. The release receipt also records each
public chunk size and the total public browser payload size. Staging case bytes
are reported separately and are excluded from the public total because their
content is already embedded in the chunks.

After all 484 cases are assembled, the retained run_419 array-level validator
loads the generated case and its chunk, cross-binds every one of the 40 current
Transolver prediction series (including both moving relative Cp grids), and
recomputes the constant-Cp segment-weighted errors:

```bash
python scripts/validate_drivaerml_native_profile_truth.py \
  --output-dir /path/to/native-profile-truth-v3 \
  --receipt /path/to/run419-validation-receipt.json
```

## Canonical identities

Coordinate, value, and raw-ID identities are independent of JSON spelling and
host byte order:

```text
coordinate = SHA256("fluidsbench-drivaerml-coordinate-array-v1\0"
                    || uint64_be(count) || binary64_be(values...))
value      = SHA256("fluidsbench-drivaerml-native-value-array-v1\0"
                    || uint64_be(count) || binary64_be(values...))
native ID  = SHA256("fluidsbench-drivaerml-native-id-array-v1\0"
                    || uint64_be(count) || uint64_be(ids...))
```

`display_coordinate_identity_sha256` uses the same coordinate-array encoding.
Materialized Cp series use `fluidsbench-drivaerml-native-series-identity-v2`,
which additionally binds the display coordinate id, unit, and array identity.
Velocity series and shared aliases retain their v1 series identity projection;
their content is unaffected by this display-only extension.

All numeric inputs must be finite; both signs of floating-point zero encode as
positive zero. A materialized series identity hashes canonical sorted compact
UTF-8 JSON plus LF over its namespace, producer support and placement
identities, component identities/counts, segment descriptors, and unsupported
samples. Document identities use the same JSON encoding over the body with the
identity field removed.

The release receipt deliberately states
`relative_scoring_activated=false`, `submissions_opened=false`, and
`owner_approval_complete=false`. Native truth publication is reproducibility
evidence, not scientific activation. Those fields describe the release receipt
when generated; the later owner scientific approval is a separate record and
the production release gates remain closed.
